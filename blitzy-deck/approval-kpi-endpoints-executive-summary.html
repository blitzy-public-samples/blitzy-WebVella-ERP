Executive Summary

Approval Dashboard KPI Endpoints

Five discrete, addressable metrics — additive and behavior-preserving.

WebVella ERP · Approval Plugin REST API v3.0
Where We Are

Today's Picture

  • A manager Approval Dashboard surfaces five live KPIs.
  • All five arrive together through one aggregate endpoint.
  • Access is restricted to manager-level roles.
One dashboard Five KPIs at a glance
Manager audience Role-gated access
Live polling Refreshes on a timer
The Change

What Changed

  • Added five discrete GET endpoints — one per KPI.
  • Each returns a single value, not the full payload.
  • Purely additive: nothing existing was altered.
Five new routes Sub-resources of the dashboard
Zero regressions Existing behavior preserved
No new dependencies One source file touched
Section One

The Five New Endpoints

One addressable metric per route

The Catalog

The Five KPIs

Recent Activity /metrics/recent-activity · list
The Contract

Endpoint, Service, Type

Endpoint (segment) Service method Returns
/dashboard/metrics/pending GetPendingApprovalsCount(userId) int
/dashboard/metrics/average-time GetAverageApprovalTime(from, to) decimal
/dashboard/metrics/approval-rate GetApprovalRate(from, to) decimal
/dashboard/metrics/overdue GetOverdueRequestsCount(userId) int
/dashboard/metrics/recent-activity GetRecentActivity(5) List<RecentActivityItem>

Each endpoint returns one typed value inside the platform's standard response envelope — not the full dashboard payload.

Consistency

Single Source of Truth

  • All routes delegate to one DashboardMetricsService.
  • Created fresh per request — no shared state.
  • Discrete values match the aggregate's components exactly.

Identical numbers No divergence
